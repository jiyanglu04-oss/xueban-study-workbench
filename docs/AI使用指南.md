# 给 AI 助手的使用与开发指南

## 三种需求要分开

1. 安装使用：只做下载、解压、运行环境准备、启动与操作说明，不改代码。
2. 排查故障：先读取可见报错与相关代码，定位原因。不要为了排查直接清空数据或重装全部环境。
3. 开发修改：用户明确要求后再编辑；在隔离数据中验证，保留用户已有改动和备份。

公开仓库链接让 AI 能读到项目说明和源码，不会自动赋予 AI 本机操作能力、教学平台登录权限或个人数据。

## 安装检查顺序

- Windows 电脑；Edge/Chrome 已安装；首次准备环境有网络。
- 完整解压，目录不是压缩包内的临时路径。
- 运行启动工作台.bat，等待环境与组件准备完成。
- 检查本机服务和 http://127.0.0.1:8765/ 页面；不要将它理解为公开网址。
- 首次向导：学期信息 → 图片识别并校对 → 自己登录平台 → 同步 → 核对结果。
- 设置作息、考试日期、备份。定时同步与提醒按用户需要分别开启，检查实际状态。
- 不接受“运行结束”作为抓取了全部信息的证明；检查平台状态和新增数据。

## 常见误判

- 收藏地址打不开：电脑重启后本机服务可能尚未启动。
- 课程少一门：先检查单双周、起止周、学期起点和当前显示周次。
- 默认明天 23:59：可能只是待办表单默认值，不是老师规定的截止时间。
- 群通知没进来：微信群、QQ 群与邮箱没有默认自动读取功能。
- 勾选已完成：只改变个人记录，不代替原平台交作业。
- MOOC 课程：放在在线学习待办和进度消息，不塞到线下固定时段课表。
- 设置了同步：不等于已经设置了提醒；电脑关机仍不会在本机继续运行。
- 旧 PDF 中的环境路径问题：v1.3.1 已增加 runtime 路径，但系统任务注册仍需实际确认成功。

## 开发入口

- backend/server.py：本地 API 和同步协调。
- backend/database.py：SQLite 持久化。
- backend/timetable_image.py：本机 OCR 与课表草稿。
- src/js/06a-timetable-import.js：导入、校对、单双周表单。
- src/js/07-onboard.js：首次向导与整个前端闭包的结尾。
- sync/adapters/：平台适配与任务整理。
- sync/register_task.ps1、sync/register_digest.ps1：系统任务，仅在用户明确需要时运行。

推荐先执行自动测试；涉及真实扫码、远程抓取或系统通知时交由用户确认和完成。不能只凭测试通过就宣称每个学校都适配。

## 分享与发布

先检查 Git 跟踪文件，再运行 tools/audit_publication.py。构建 HTML 必须没有个人同步快照。源码包、教程和截图使用演示数据，不能把个人数据带入 GitHub。

不擅自改变仓库可见性、添加许可证、提交云端配置或以用户身份发布其他内容。发布权限以用户本次明确请求为准。
